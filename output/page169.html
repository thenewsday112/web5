The agent has finished the bulk of your change. Now you want to inspect one implementation detail, adjust a few lines by hand, and run the project locally before you ship it.

But the work is sitting in the GitHub Copilot app… and your editor is where you review diffs, debug code, and make final adjustments. Do you have to choose between staying in the session and starting over in Visual Studio Code?

You don’t. You can open the Copilot app session directly in VS Code and continue with its conversation, code changes, and working context intact. That means Copilot can handle the repetitive or time-consuming work, then hand control back to you for closer review, hands-on editing, and local testing.

In this tutorial, you’ll learn how to:

  • Open a Copilot app session in VS Code.
  • Review the agent’s changes line by line.
  • Continue the same conversation from your editor.
  • Modify and test the code locally.
  • Push your updates to the pull request associated with the session.

Prerequisites 

Before you begin, make sure you have: 

  • The GitHub Copilot app installed and signed in. 
  • Visual Studio Code installed and connected to the same GitHub account. 
  • A Copilot app session with code changes you want to review or continue. 
  • Permission to work in and push changes to the session’s repository. 

This tutorial assumes you are already comfortable navigating VS Code, running commands in its integrated terminal, and working with Git branches and pull requests.

1. Start with a session in the Copilot app

Open the session you want to continue. Before handing it off, take a moment to review the task and the work Copilot completed.

A session contains more than a collection of modified files. It also records the task, the plan, and the conversation that produced those changes. That context is important when you want to understand why Copilot chose a particular implementation or ask it to revise part of the work.

You do not need to summarize that history or copy it into a new chat before moving to VS Code.

2. Open the session in VS Code

From the session, select Open in VS Code. If the app presents more than one supported editor or VS Code installation, choose the one you want to use.

VS Code opens the project using the worktree associated with the session. It also displays the existing session in the Copilot sidebar.

That gives you three connected pieces of the original work:

  • The session context: The task, plan, and conversation remain available.
  • The diff: The files and lines changed by the agent are ready for review.
  • The worktree: VS Code opens the same isolated working tree the session used.

You are continuing the existing session, not reconstructing it in a new editor window.

3. Review the agent’s changes

Before editing, inspect the diff in VS Code. Open the Source Control view to see the changed files, then select a file to review its changes line by line.

Review the implementation as you would any other proposed change. In particular, check that:

  • The code solves the requested problem.
  • The implementation follows the repository’s conventions.
  • Error states and edge cases are handled appropriately.
  • Tests cover the behavior that changed.
  • No unrelated files or behaviors were modified.

The preserved conversation can help explain how Copilot arrived at the implementation. If something is unclear, continue prompting Copilot in the sidebar. For example:

Explain why you changed this function instead of adding a new helper. Identify any behavior this could affect.

You can also ask Copilot to make another change. Because the session and worktree remain connected, you do not have to describe the task from the beginning.

4. Make a hands-on edit

Once you understand the proposed changes, edit any file directly in VS Code.

This is useful for adjustments that are faster or easier to make by hand, such as:

  • Refining a label or error message.
  • Renaming a variable for clarity.
  • Adjusting layout or styling.
  • Adding a missing test case.
  • Applying a repository-specific convention.

You are editing the session’s existing worktree, so your manual changes build directly on the agent’s work. You do not need to copy files between directories or manually re-create the branch.

5. Run and verify the project locally

Use the VS Code integrated terminal to run the project’s normal validation workflow. The exact commands depend on the repository, but some web app examples may include:

  • npm install
  • npm test
  • npm run lint
  • npm run dev

Treat agent-generated changes the same way you would treat code written by a person: run the relevant tests, inspect failures, and verify the behavior yourself.

If the development server prints a localhost URL, open it to test the change in a browser. When supported by your VS Code setup, you can open the URL in VS Code’s integrated browser and inspect the result without leaving the editor.

For a user-interface change, verify both the requested behavior and nearby states. For example, check the modified component at different viewport sizes and confirm that loading, empty, and error states still work.

6. Continue with Copilot or keep editing yourself

At any point, you can choose the interaction that best fits the next step:

  • Prompt Copilot when the change requires repository-wide analysis or repetitive edits.
  • Edit directly when you know the exact change you want.
  • Use both approaches iteratively as you test and refine the implementation.

For example, after making a manual UI adjustment, you might ask Copilot:

Add a test for the updated label and run the relevant test file. Do not modify unrelated components.

Because you are still in the original session, Copilot retains the context needed to interpret “the updated label.”

7. Commit and push the finished changes

When the implementation is ready, review the final diff one more time. Then commit and push the changes using the Source Control view or the integrated terminal:

  • git status
  • git add
  • git commit -m "Refine session changes"
  • git push

Use your repository’s normal branch, commit, review, and approval practices. Because VS Code opened the worktree and branch associated with the session, pushing the branch updates the pull request already tracking that work.

There is no need to copy the finished files into another checkout or reconnect the work to the pull request manually.

A continuous workflow from agent to editor

Opening a Copilot app session in VS Code gives you a clean division of labor without splitting the work itself. Copilot can take on a larger or repetitive implementation, while you can move into the editor for detailed review, targeted changes, local testing, and final polish.

The session, diff, and worktree move with you. Start by directing the work in the Copilot app, switch to VS Code whenever you want hands-on control, and push the finished result through the same pull request workflow.

Ready to try it? Download the GitHub Copilot app, start a session, and open it in VS Code when you are ready to continue coding.

What a Fictional Robot Can Teach Us About Care

📅 Oct 19, 2026  |  Category: Technology  |  Read Source →

This essay contains mild spoilers for the novel Klara and the Sun.

The baby, my baby, was to be named Josie. Josie Joy.

But when she was born, she was decidedly not a Josie. The name was too soft, too ethereal for such a sentient, wide-awake, bird-like baby. I knew that I had to find a new name. Who are you? I whispered into the swirls of her astoundingly warm, circulated, and singularly perfect ear. I couldn’t wait to get to know her.

In another story, a girl named Josie is dying. In Kazuo Ishiguro’s 2021 novel Klara and the Sun, Josie has an unknown illness and a prognosis that haunts the pages. Her life exists in the shadow of her sister, Sal, who has already died of the same unarticulated illness, likely caused by an elective genetic alteration procedure known as “lifting.”

In Josie’s world, being lifted is the new social currency; those who are lifted are expected to have greater access to both intellectual and economic success. The procedure does not, however, come without risk. When we meet Josie’s mother, she is tasked with the impossible: coping with the impending death of her only remaining child. A death likely resulting from a choice she made as a parent. The ultimate consequence.

Klara is a robot purchased by Josie’s mom to be her companion, in part (it is implied) to assuage the guilt she feels. I first read Ishiguro’s Klara and the Sun shortly after its debut. Despite being disturbed by some aspects of the dystopian world depicted within, my memory of the novel was poignant. I recalled Klara with particular affection.

Now, the distance between Ishiguro’s dystopian world and our current reality is rapidly collapsing. With the much anticipated film adaptation set to be released this Friday, October 23, and the sudden ubiquity of artificial intelligence in our day-to-day lives, Klara and the Sun is now repositioned as a mirror. If we look closely enough, we might discern what remains uniquely human during this moment of profound technological and social change.

Care through other eyes

We are introduced to Klara, the story’s narrator, when Josie’s mom takes her to find an artificial friend, or AF for short. In the novel, AFs confer social standing, but also offer practical assistance—tutoring, companionship, monitoring an ailing child—not unlike the benefits purported by artificial intelligence companies today.

Klara has been patiently waiting, alongside several other AFs, to be chosen. Josie’s mother is the final decider. In a foreboding scene, Josie’s mother commands Klara to reenact Josie’s gait—a test, of sorts—before agreeing to purchase her. It’s the precision of Klara’s mimicry that convinces “the Mother” (as she’s called in the novel) that Klara is the right model for Josie.

All of this, we learn through Klara. Ishiguro’s choice to position the reader within Klara’s perspective allows us to bypass the quagmire question of whether or not Klara is conscious and instead project our own consciousness onto her. In doing so, we view the human world through her sometimes malfunctioning robot eyes, as she nonjudgmentally conveys the complexities of the very flawed and sometimes desperate human behaviors she seeks to understand. In one particularly moving scene, Klara witnesses the vulnerability of caring for another human being:

I saw before me, on the near edge of the bed, a large shifting shape, made additionally complex by the patches of blackness and moonlight moving over its surface. I realized the shape was the Mother and Josie embracing. . . . As well as their limbs, their hair had become mingled, and then their shape began gently to rock, in a way not unlike when their goodbyes became extended.

“Don’t want to die, Mom. I don’t want that.”

“It’s okay. Okay.” The Mother’s voice was soft, at just the same level mine had been.

“I don’t want that, Mom.”

“I know. I know. It’s okay.”

Prior to this moment, Klara—steadfast and ever-available—had offered her presence to comfort Josie. Yet, despite their far more complicated and at times strained relationship, it is the Mother that Josie calls for.

Care creates love

When I first became a parent, I confided to a friend that when my not-Josie was born, I felt like a new sun had burst into my solar system, and I was now orbiting around her. I couldn’t quite articulate the “before,” in my metaphor. I didn’t feel like I was previously my own sun, nor did I feel like I was a planet untethered to others. But there was something distinctly different when she arrived, a whole new consciousness, a space and force and awareness created within me. Her pull was intoxicating, undeniable, sometimes terrifying, and my awareness and attention seemed to expand overnight to now include not only my own experiences, but also to track, perceive, anticipate, and accommodate her own.

If Klara had turned to psychological theory and research about the complexity of parent-child bonds, she would have found a great deal of it. Consider Winnicott’s “good-enough mother” or research indicating that parents and infants are rarely, if ever, perfectly attuned, and the growing body of evidence suggesting that the navigation of the ruptures and repairs themselves reinforce attachment. It has become increasingly clear through evolving applications of experiments such as Edward Tronick’s now famous “still-face” experiment that the imperfect dance between caregiver and child lays the groundwork for resilience and emotional regulation.

In The Philosophical Baby, developmental psychologist and philosopher Alison Gopnik says, “It’s not so much that we care for children because we love them, as that we love them because we care for them.”

We love them because we care for them.

Beyond Gopnik’s own research, there is an abundance of data to back this up. Studies I have long been familiar with, such as those demonstrating that in same-sex, non-carrying male couples, fathers who act as primary parents show changes in similar brain regions to women who carried their pregnancies and go on to parent their children. Yet, there was something profound about the simplicity of Gopnik’s statement, about love being something we cultivate within ourselves and, more precisely, about care being the means through which we build love, not merely a necessary byproduct.

In a separate interview, Gopnik jokes that spending time with a three-year-old gives you a small taste of sainthood. Not in the sense that the demands are so extreme that you inherently become a saint (though there is a real argument to be made here for any parent who weathers the storm of a parking lot tantrum), but in the actual felt-sense of the divine, the experience of feeling so acutely and utterly in love with this being, so in awe of their singularity, their specialness, their openness to experience, their brilliance.

Gopnik continues on, teasing, about our tendency to claim the uniqueness of our three-year-old, in her case her grandchild, but gently affirms the truth beneath: that there is something numinous, universal, pure within all three-year-olds, a near-magical vitality that we sometimes make contact with when we intimately care for one. Something primal, or perhaps primary, is awoken when we re-experience the world through the eyes of a three-year-old.

Care and distance

My not-Josie is now three. In many ways she is more unknowable, separate, than she was when she was a newborn, so physically attached and dependent on me. Now, she has her own relationships—with teachers, classmates, family members—that are entirely her own. And yet, she occupies and orients so much of me, continually changing my experience of the world, my access to play, to awe, to unadulterated, intoxicating adoration. 

This past summer, I was sitting by a lake, relaxed but hawk-eyed as I watched my not-Josie from the shore. I felt a familiar presence by my side, the barely-perceptible shadow in my peripheral vision of a small body sitting down, and soon thereafter, the unselfconscious weight of a small hand on my leg. I looked down to see a head covered in feathery blonde hair, not the dark, curly brown of my own child.

The wispy tufts belonged to another small child who had clearly mistaken me for her mother. In that brief moment before she looked up, before we both acknowledged our separateness, I felt overcome with the awareness—as though received through the touch of her hand on my leg—that her mother loved her in the way that I love my child, and that, despite how unbelievably special my not-Josie is, my love for her is not. It is precious, but also universal.

Intellectually, of course, this is not a profound realization. Emotionally touching into it is, on the other hand, equally as brutal as it is beautiful. Next to this small child, healthy and safe, I felt her preciousness, but also that of all the children flooding my news feed every day who are not healthy and safe, and whose parents must live with this love and that devastation.

Care and consciousness

On the back cover, Klara and the Sun is described as a story about love, which it undeniably is. But I think it’s perhaps more fundamentally about care.

Care is arguably more tangible than love, but also more complex, friction-prone, messy. It’s the gaps, the mistakes, the harms, the repairs, the precarity, the forgiving, that make care so deeply painful and so deeply nourishing. Nourishing enough to sustain the vulnerability of love.

It is care that drives Josie’s mother to have her “lifted” in an age-old attempt of desperation to give her child what she perceives as the best chance at a full life in a rapidly reorganizing world. It is care that sends the Mother down the path of trying to find a way to have Klara “continue” Josie’s life, even though she has already tried and failed to recreate her first child’s consciousness in an artificial intelligence through the work of an artist and scientist named Capaldi.

It is care that allows the Mother—despite her cold exterior—to fearlessly comfort her child as she confronts the possibility of her own death, enveloping her, rocking her, soothing her through the unimaginable. It is the Mother’s human care, not her cowardice, that makes her love true.

There is so much in Klara and the Sun that is undeniably relevant in this particular social, cultural, and technological moment, so many ways in which Ishiguro’s Josie and my not-Josie’s world are suddenly uncomfortably proximate, but it is what Klara herself affirms about humanity that is most resonant.

At the end of the novel, Klara reflects on what she’s learned. She did not have to become a Josie 2.0, for Josie survived. Klara is glad for this, of course, believing that it was her bargain with the Sun (which she sees as a kind of god) that saved Josie. Sitting discarded in a junk yard, Klara is increasingly convinced that the desperate plan to turn Josie into a digital consciousness wouldn’t have worked:

Mr. Capaldi believed there was nothing special inside Josie that couldn’t be continued. He told the Mother he’d searched and searched and found nothing like that. But I believe now he was searching in the wrong place. There was something very special, but it wasn’t inside Josie. It was inside those who loved her. That’s why I think now Mr. Capaldi was wrong and I wouldn’t have succeeded.


It is what happens within us and between us when we care for another being that differentiates us as humans. In other words, it’s not so much what’s there but what’s not there—the space between the person in front of us and how we perceive, imperfectly care for, and ultimately love them—that makes us human.

Through Klara’s eyes, I was able to see more clearly what connects the Mother and her Josie to me and my not-Josie. It is the very fact that we can so wholeheartedly love another being, without being them, having them, solving them, knowing every bit of them. It is the fact that still, we carry them in our hearts, and somehow we are not heavier for it.

AWS Weekly Roundup: AWS Lambda Web Functions, Amazon S3 on the Vercel Marketplace, and more (October 19, 2026)

Nothing last week added a new kind of compute. What it did instead was shorten the distance between the code you already have and that code being live. AWS Lambda learned to run a plain HTTP server with no adapter in front of it, and Amazon S3 became something you can provision from inside the tool you were already using, without opening the AWS Management Console. Different services, same direction.

The counterweight arrived on Thursday. As it gets easier to put things into production, it matters more that you can say what those things are allowed to do, and this week’s most interesting read is about exactly that. Now, let’s get into this week’s AWS news…

Headlines
AWS Lambda Web Functions is a new form factor that runs a standard HTTP web application on Lambda without rewriting it into an event handler. You take a port-listening server built with Express, Hono, Fastify, or Next.js, run aws lambda-web deploy, and get back a live HTTPS URL in under a minute. No adapters, no infrastructure to set up first, no framework lock-in. Lambda now has three form factors on the same Firecracker isolation, which compose inside one application: Event Functions (the model you already know) for async work, Web Functions for the user-facing layer, and MicroVMs for stateful sandboxes running untrusted code.

Two details make this more than repackaging. Each execution environment handles up to 128 concurrent requests, so a burst of traffic shares warm environments instead of mapping one request to one environment, and billing meters the CPU time your code actually uses rather than wall-clock time. For server-side rendering, API backends, and inference endpoints streaming tokens, where most of the elapsed time is spent waiting, that changes the arithmetic. Adding --regions to the same deploy command replicates your code and configures latency-based routing behind a single global URL, and you can split traffic across revisions by weight for a canary rollout. It’s available in five Regions, running Node.js 24 on Arm64 with VPC connectivity. The AWS Compute Blog has a longer walkthrough, and Amazon CloudFront can now use a Web Function endpoint as an origin with origin access control.

The week’s other headline isn’t a launch. Trust in Depth: giving agents more autonomy without losing control makes an argument I keep running into in practice: putting a person in the loop for every agent action works at small scale and then quietly stops working, because people asked to check everything stop catching what matters. The alternative is four questions answered at four moments, which AWS calls scope, know, bound, and observe. The part worth sitting with is that an agent’s limits belong outside its own reasoning, in Amazon Bedrock AgentCore policies enforced at the gateway, because an agent cannot turn off a control it does not run. AWS has run automated reasoning in production for more than a decade, including AWS Identity and Access Management at more than 2.1 billion requests per second, and the case here is for pointing it at the rules you write for agents.

Last week’s launches
Here are some launches and updates from this past week that caught my attention:

  • Amazon S3 is now available on the Vercel Marketplace and v0 by Vercel – You can now provision S3 general purpose buckets, S3 Tables, and S3 Vectors from the Vercel dashboard, or by describing what you want to build in v0. It joins existing integrations for Amazon Aurora, Amazon DynamoDB, and Amazon OpenSearch Serverless, so the whole stack sits in one AWS account with one bill. The authentication detail is the good part: a short-lived OIDC token is exchanged at runtime with AWS Security Token Service for credentials scoped to that resource, so no static keys are stored anywhere.
  • Amazon EC2 T8i instances are now available in South America (São Paulo) – The newest burstable generation reached the São Paulo Region, which matters for the unglamorous half of a workload: login gateways, small databases, CI/CD runners, low-traffic sites. Amazon EC2 T8i delivers up to 30 percent better price performance than T3, with up to 70 percent higher compute performance and 2.4 times the Amazon EBS bandwidth. It keeps the same CPU credit system as T3, so moving over is a size change rather than a redesign, and t8i.micro and t8i.small are available under the AWS Free Tier.
  • Reflection Beam, an open-weight model for agentic coding, is now on AWS – You can now deploy Beam, Reflection AI’s open-weight model for agentic coding and long-horizon tasks, from Amazon SageMaker JumpStart. It’s a sparse mixture-of-experts model with 501 billion total and 23 billion active parameters, released on Hugging Face under Apache 2.0, and Reflection reports an effective context length of 1 million tokens. Start with a JumpStart real-time endpoint, or use SageMaker HyperPod Inference with SGLang or vLLM when you need Kubernetes-native control. It was also ported and optimized for AWS Trainium3, and launches in N. Virginia and Ohio.
  • AWS Lambda Durable Execution SDK for Go is now generally available – You can now write multi-step Go workflows that checkpoint their own progress and pause for up to a year while waiting on an external event, without building progress tracking yourself.   • Amazon CloudWatch announces log routing and chained log parsers – You can now define routes in an Amazon CloudWatch pipeline that send each event to a different log group based on conditions evaluated against processed fields, so severity, source, or event type can each land somewhere with its own retention and access controls. Chained parsers handle the other half: parsers run in sequence, with later ones consuming fields that earlier ones produced, so you can parse a JSON envelope first and then run a Grok parser over a field it extracted.

Feds Suspect Ransom Negotiator Ran ShinyHunters Extortion Site

📅 Oct 19, 2026  |  Category: Technology  |  Read Source →

U.S. federal investigators pursuing the ShinyHunters hacking group that recently stole highly sensitive data from the FBI have identified executives at two different ransomware negotiation firms who maintained unusually close relations with the extortion group, KrebsOnSecurity has learned. Sources close to the investigation say one of the executives in the United States even helped ShinyHunters operate a website that pressured victims into paying a ransom.

Hackers aligned with ShinyHunters have claimed credit for dozens of major data breaches since 2019, when the group was primarily operated by cybercriminals living in France. As those original members were arrested or jailed one by one, control over the ShinyHunters brand eventually passed to “Rey,” identified last year as a teenage hacker from Amman, Jordan. According to the FBI, ShinyHunters has extorted more than $70 million from victims so far this year.

In late September, ShinyHunters hacked the FBI recruitment website fbijobs.gov and taunted the agency by threatening to publish the stolen files, which reportedly included medical and psychological records, Social Security numbers and home addresses, and information about each employee’s unit and specialization.

The FBI jobs site hack has prompted the agency to move with uncommon speed to arrest, detain and question people who had any communications with Rey or other ShinyHunters suspects. Reuters reported on October 3 that Rey had been detained by Jordanian authorities and was cooperating with the FBI.

Rey was able to assume control over the hacking group because one of its alleged senior members had just been nabbed. On the evening of September 15, 2026, authorities in the Netherlands arrested convicted hacker and ShinyHunters suspect Pepijn van der Stap. Dutch police reportedly used flash-bang grenades in an effort to stun and apprehend Van der Stap as he was logged in to various online accounts.

According to a source close to the investigation, the authorities arrested Van der Stap while he was using his Signal instant messaging account, which allowed them to read recent communications with frequent contacts — including ransomware negotiators based in Canada and the United States.

Multiple sources with knowledge of the matter told KrebsOnSecurity that Van der Stap’s messages were the key to unraveling a murder-for-hire plot that emerged immediately following his arrest. The Dutch news outlet RTL reported last month the two murders were allegedly to be committed abroad, and that there are indications Van der Stap gave the order for the attacks (there is no indication those orders were ever carried out).

On October 9, KrebsOnSecurity broke the news that the FBI arrested a 54-year-old Canadian cybersecurity executive named Edward Dubrovsky in connection with the ShinyHunters investigation. Dubrovsky, who recently published a book on handling cyber extortion that recommended always engaging with the hackers, was charged with threatening to disclose stolen or hacked data and interfering with interstate commerce through extortion, according to court records. Politico reports prosecutors have asked that Dubrovsky remain in custody pending trial, and that records related to his case remain under seal.

A source close to the investigation told KrebsOnSecurity that Van der Stap’s Signal messages showed he had frequent conversations with Mr. Dubrovsky and with at least one executive at a large U.S.-based consulting firm, and that these executives often knew the details about new ShinyHunters victims before the victims themselves had even learned of the breach.

That source shared another potentially explosive finding by federal investigators: the Dutch hacker’s chats showed Mr. Dubrovsky knew ShinyHunters had stolen highly sensitive data from FBI servers, and that he never informed the bureau of the data breach prior to ShinyHunters threatening on Twitter/X to publish the agency’s deeply personal personnel files.

SHINYWIRE

KrebsOnSecurity has learned from two sources close to the ShinyHunters probe that FBI investigators believe at least one executive at a U.S.-based consulting firm played an active role in operating the now-defunct ShinyHunters victim extortion website “shinywire[.]com.” KrebsOnSecurity is not naming the U.S. company or the suspected executive(s) for now because they have not yet been charged with a crime, but it is a prestigious firm with more than 1,000 associates.

A section of the homepage for the now-defunct Shinywire website.

The Shinywire website was active from approximately May 3, 2026 until October 16 and had entries for nearly 100 organizations hacked by ShinyHunters. Each entry urged victims to engage with the cybercrime group and discuss terms for payment. The pages also included samples of stolen files and promised those files would be published online if the victim ignored their demands.

The following screenshot shows a cached portion of the Shinywire extortion page for Intuitive Surgical, an American medical technology company that was breached in March 2026 after an employee fell for a targeted phishing email.

The Shinywire website, as indexed by urlscan.io. This listing is an extortion demand targeting Intuitive Surgical, an American medical technology company breached in March 2026 by a targeted phishing email attack that compromised an employee’s credentials.

Victim organizations that refused to engage or negotiate after seven days would find all of their stolen data published on the ShinyHunters victim shaming blog (a website that is only reachable via the anonymity network Tor).

In a story published October 15, The Globe and Mail wrote that a few months before Edward Dubrovsky was arrested by the FBI, the Canadian cybersecurity executive alleged in court documents he had become collateral damage in a campaign by a former business partner to “destroy” another industry executive.

The story noted that Dubrovsky filed the lawsuit in Ontario this year against Daniel Tobok, the former chief executive of Cypfer, a cybersecurity firm founded in Toronto with offices in the U.S., Britain, the Netherlands, the United Arab Emirates, and Mexico. The two first became business partners in 2017 and later developed Cypfer together, where Mr. Dubrovsky was a managing partner and chief operating officer. But by 2024, the two had a falling out, with Dubrovsky accusing Tobok of gradually excluding him from business matters and making “increasingly capricious business decisions.”

Mr. Tobok reportedly denied the allegations and filed a counterclaim, accusing Mr. Dubrovsky of accessing confidential information and unfairly competing with Cypfer through work at another firm called CyberSteward Inc. He also said Mr. Dubrovsky has misrepresented himself as a Cypfer founder, and is not a shareholder.

GHOSTBYTE

According to interviews with several former colleagues of Mr. Tobok, as far back as eight years ago he was known to ransomware purveyors by a particular nickname: Ghostbyte. In 2018, a Canadian company was hacked by Dharma, a prolific Russian-language ransomware affiliate program that first surfaced in 2016. The victim company told the Dharma ransomware representative they were leaning toward paying because some of the files were unrecoverable after being locked, but that they needed a better guarantee that Dharma would keep their word if paid.

A redacted copy of the Dharma rep’s reply is pictured below, and it shows the ransomware group urged the victim to contact a person at a Canadian IT firm that helps companies seeking such guarantees. The Dharma rep recommended the victim contact the email address ghostbyte@tutanota.com.

“If you want guarantees, you can write to the IT company,” the Dharma reply advised. “Take the phone and negotiate with them. This IT company often solves such problems in Canada. You can contact them and sign a contract for services. You’ll still have to pay.”

An email reply from the Dharma ransomware group to a victim, recommending they contact an email address that is connected to Mr. Tobok.

It’s unclear if Mr. Tobok ever used that Ghostbyte address offered by the Dharma representative, and he has not responded to multiple requests for comment. However, the breach tracking service Constella Intelligence finds an email address Mr. Tobok has frequently used — dtobok@me.com — is associated with two online accounts where the chosen username was “ghostbyte,” including a Snapchat account.

Incidentally, Constella also finds the Dharma rep’s email address luckygoodlucky@tuta.io is associated with a cryptocurrency address that processed 38 transactions totaling 43 bitcoin, ~$3.5 million at today’s value (the most recent transaction for this wallet is dated February 2019).

In a statement shared on October 14, Cypfer said the company’s business does not include making or facilitating ransomware payments, and that Cypfer learned of Dubrovsky’s arrest when the news first broke in the media.

“We had no prior knowledge of Mr. Dubrovsky’s arrest,” a spokesperson told KrebsOnSecurity via email. “CYPFER has not received any outreach from law enforcement and, to our knowledge, is not the target of any law enforcement investigation.”

The statement said CyberSteward and Cypfer are separate companies with no officers, directors or employees in common, and that Cypfer was recently acquired by the Apros Group, a holding company led by Jason Hogg, a former FBI special agent and former CEO of Aon Cyber Solutions Group. In 2020, Aon aquired Cytelligence, a security consulting firm where Mr. Tobok was founder and CEO and Mr. Dubrovsky was a managing partner.

CONFLICTING INTERESTS

It is not illegal in the United States to pay hackers for an encryption key to unlock servers infected with ransomware, or in exchange for a promise to delete any stolen files and refrain from publishing them online. While victim organizations can land in legal hot water if they pay a ransom to a group that is sanctioned by the U.S. Treasury Department, ShinyHunters is not among the ransomware groups currently sanctioned by the United States or by any other government.

Experts say ransomware victims are typically directed by their insurance provider to work with a specific incident response firm. But not all cyber forensics and breach response companies will agree to facilitate payments to ransomware groups on behalf of their clients. As a result, once victim firms make a decision to pay, the firms that eschew rewarding extortionists are invariably replaced by companies that have no such qualms.

In December 2024, ShinyHunters began extorting the education technology company PowerSchool, stealing private information on 62 million students and 9.5 million teachers in the U.S. and Canada. PowerSchool reportedly paid a $2.85 million ransom demand, and a “frequently asked questions” statement (PDF) about the breach says PowerSchool was assisted in that effort by CyberSteward (ShinyHunters affiliate Matthew Lane, 20, of Sterling, Mass., was sentenced in November 2025 to four years in prison for his admitted role in the PowerSchool hack).

But that ransom payment did not stop future extortion attempts using the same stolen data. By May 2025, individual school districts were reportedly receiving separate ransom demands using samples of the same stolen files. While nobody has alleged ShinyHunters was behind the second wave of extortion against PowerSchool users, the incident drives home the reality that there is no technical way to verify the threat actors have deleted the stolen data as promised, or prevent others from abusing the same records.

A number of leading cyber incident response firms, including Coveware and Unit 221B, have consistently warned victims against paying ShinyHunters, noting that “destroyed” victim data is often kept, resold or used to extort the company’s clients directly later on.

The FBI echoed those sentiments in an alert on May 15, 2026 advising victims against paying the ShinyHunters group. Meanwhile, ShinyHunters members have been harassing and threatening employees at Coveware and Unit 221B for offering this advice.

The following screenshots show just how annoyed the ShinyHunters leaders were with Coveware’s relentless advice against paying the group. The first image is from a conversation on May 6, 2026 that took place between the group’s main account on Telegram and a co-conspirator. In that chat, snippets of which were shared with KrebsOnSecurity by a trusted source, ShinyHunters complained that Coveware was harming the group’s payment rates.

The operator of the ShinyHunters account on Telegram speaking privately with a co-conspirator and complaining that Coveware was harming their business.

“Go on my website, majority of those companies would’ve paid if it weren’t for Coveware giving them misinformation,” the ShinyHunters account wrote. “Someone (100% Coveware) is going out of their way to make sure i am not paid.”

In another conversation on April 11, 2026, the ShinyHunters Telegram account privately said they were trying to “eliminate the problem,” which they said was Coveware. Coveware declined to comment for this story.

“I’m sure the company will pay but in this specific case I am aware of Coveware and their involvement, and I’ve probably been not getting a lot of other negotiations mostly likely because Coveware keeps getting involved,” the ShinyHunters account bemoaned.

The operator of the ShinyHunters account on Telegram telling a co-conspirator they were “trying to eliminate the problem,” which they identified as Coveware advising victims not to pay the cybercrime group.

Mark Camillo is chief executive at CyberAcuView, an industry group founded in 2021 by a consortium of major cyber insurance carriers. Camillo said some firms charge a flat retainer fee, while those that specialize in helping companies negotiate a ransom payment tend to charge a percentage of the total ransom amount paid.

That latter dynamic, he said, is an inherent conflict of interest, as the negotiator has every incentive to make things more favorable to the attackers because they are financially incentivized to negotiate and pay out, and to not negotiate down on the price.

“It has come to the industry’s attention that many of the ransomware payers charge a percentage of the final payment which may or may not be disclosed,” Camillo said. “This makes no sense if they are also the negotiator. There needs to be more transparency in the process as no one in the ecosystem should be profiting purely on the size of the ransomware transaction or payment itself.”

Camillo said the firms doing this work would argue the fees are needed because there may be unexpectedly higher costs to secure larger quantities of cryptocurrency or more risk carrying the float, and because cryptocurrency exchanges may charge higher fees for high risk transactions.

“There definitely needs to be more visibility around the transaction and clarity on the increasing value of the crypto and the exchange’s percent in the transaction to get to the bottom of this and remove any misaligned incentives,” he said.

In recent months, the U.S. Department of Justice has prosecuted a number of ransomware negotiators alleged to have conspired with cybercriminals to defraud their clients. On October 7, the DOJ charged MonsterCloud CEO Zohar Pinhasi, 50, with wire fraud and conspiracy for allegedly charging customers to remediate ransomware attacks without paying the hackers. According to charging documents, Pinhasi secretly went behind his customers’ backs and paid hackers anyway, paying ransomware groups $8 million while charging customers $19 million.

In July, Angelo Martino, a 41-year-old ransomware negotiator from Land O’Lakes, Florida, was sentenced to 70 months in prison for conspiring with the Blackcat/ALPHV ransomware group to extort multiple victims. According to the DOJ, Martino was paid by BlackCat attackers to provide confidential information about the negotiating position and strategy of his employer’s clients and enable the ransomware actors to maximize the ransoms paid by the victims.
